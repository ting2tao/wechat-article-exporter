# 定时任务显式选择公众号与逐篇导出格式设计

## 背景

当前后台定时任务存在两个影响可用性的问题：

1. 定时同步与定时导出默认缺少精确范围控制，用户无法显式指定任务公众号与导出格式。
2. 设置页每 15 秒轮询一次服务端快照，并且会无条件覆盖本地表单，导致用户在尚未保存时看到开关或输入内容被“自动改回去”，表现为“开启后自动关闭”。

这两个问题叠加后，用户既无法精确控制任务对象，也无法稳定配置定时任务。

## 目标

- 定时任务不再默认作用于全部公众号，必须由用户显式选择公众号后才会执行。
- 定时同步与定时导出复用同一组已选公众号范围。
- 定时导出不再默认固定为 HTML，必须由用户显式选择逐篇导出格式。
- 定时导出仅支持逐篇格式：`HTML`、`TXT`、`Markdown`、`DOCX`。
- `Excel`、`JSON` 保持手动导出，不进入定时任务。
- 当未选择任何公众号时，任务保持启用状态，但本轮执行应被安全跳过，并给出明确摘要。
- 当未选择任何导出格式时，导出任务保持启用状态，但本轮执行应被安全跳过，并给出明确摘要。
- 设置页轮询不得覆盖用户尚未保存的编辑内容。

## 非目标

- 不为“公众号同步”和“定时导出”分别维护两套不同的公众号选择。
- 不将 `Excel`、`JSON` 改造成后台定时任务产物。
- 不改变现有托管公众号的来源与维护方式，账号页仍然负责向服务端写入可选账号池。
- 不新增复杂的调度策略，例如按账号设置不同间隔或优先级。

## 当前实现问题

### 任务范围

- `server/services/worker/scheduler.ts` 中的同步任务直接遍历 `listTrackedAccounts()` 返回的全部账号。
- 当前后台导出能力固定为 HTML 下载，且通过 `downloadPendingHtmlBatch()` 统一处理待下载文章，既未按公众号范围过滤，也不能按格式选择。
- 设置配置 `WorkerSchedulerConfig` 中不存在任务公众号与导出格式字段，因此前端无法表达“只运行部分公众号”和“只导出某些格式”。

### 设置回弹

- `components/setting/Schedule.vue` 每 15 秒执行 `refreshSnapshot()`。
- `applySnapshot()` 会无条件将服务端配置回写到 `form`。
- 当用户编辑但尚未保存，或者保存失败后，轮询就会把本地表单恢复成旧值，造成“自动关闭”与“输入被吃掉”的观感。

## 方案概述

采用单一配置源方案：在后台任务配置中新增 `selectedAccountFakeids` 与 `selectedExportFormats` 两个字段，分别保存“当前允许参与定时任务的公众号 fakeid 列表”和“当前允许后台逐篇导出的格式列表”。

同步任务与定时导出任务均只读取 `selectedAccountFakeids` 作为范围约束；导出任务额外读取 `selectedExportFormats` 决定要生成哪些文件。

同时，在设置页引入“表单脏状态”保护。用户修改表单后，在未保存前，轮询只更新运行状态和统计信息，不覆盖本地编辑值。

## 数据模型调整

### `WorkerSchedulerConfig`

新增字段：

- `selectedAccountFakeids: string[]`
- `selectedExportFormats: Array<'html' | 'txt' | 'markdown' | 'word'>`

语义：

- 为空数组表示“未选择公众号”，不是“全部公众号”。
- 后台任务在配置启用但列表为空时，应跳过执行并输出说明。
- `selectedExportFormats` 为空数组表示“未选择导出格式”。
- `selectedExportFormats` 仅允许逐篇格式，明确不含 `excel`、`json`。

### SQLite 配置表

`worker_scheduler_config` 新增列：

- `selected_account_fakeids TEXT NOT NULL DEFAULT '[]'`
- `selected_export_formats TEXT NOT NULL DEFAULT '[]'`

存储规则：

- 使用 JSON 字符串持久化数组。
- 读取时进行 JSON 解析，解析失败则回退为空数组。
- 写入时去重、过滤空值，并统一序列化。

### 快照接口

`/api/web/worker/scheduler` 的读写响应中都增加：

- `selectedAccountFakeids`
- `selectedExportFormats`

## 前端设计

### 设置页展示

在“公众号同步 / 定时导出”设置区域中新增两个显式选择控件：

- 公众号多选：
  - 数据源：服务端已托管公众号列表。
  - 展示信息：公众号昵称，必要时附带 fakeid 作为辅助识别。
  - 支持多选。
  - 文案明确说明“后台同步与定时导出都会限制在这里选中的公众号范围内”。
- 导出格式多选：
  - 固定候选：`HTML`、`TXT`、`Markdown`、`DOCX`。
  - 明确标注 `Excel / JSON` 仍需手动导出。

导出卡片不再写死为“HTML 下载”，而是调整为更准确的“定时导出”，并展示当前选中的逐篇格式。

### 表单状态

新增本地状态：

- `selectedAccountFakeids`
- `selectedExportFormats`
- `isDirty`

行为规则：

- 用户修改任一字段后，将 `isDirty` 置为 `true`。
- 轮询刷新时：
  - 始终更新运行状态、执行结果、统计值。
  - 仅当 `isDirty === false` 时，才完整回写配置表单。
- 保存成功后：
  - 用服务端返回值完整回填表单。
  - 将 `isDirty` 重置为 `false`。
- 保存失败后：
  - 保留本地编辑值，便于用户继续调整或重试。

## 服务端行为设计

### 同步任务

执行流程调整为：

1. 读取配置中的 `selectedAccountFakeids`。
2. 从 `listTrackedAccounts()` 中筛出被选中的账号。
3. 若筛选结果为空：
   - 不报错。
   - 更新 `lastSyncFinishedAt`、`lastSyncSummary`。
   - 摘要内容为“未选择公众号，已跳过本轮同步”。
4. 若有选中账号，仅同步这些账号。

### 定时导出任务

定时导出服务需要同时支持：

- 按 fakeid 集合过滤文章范围
- 按格式集合生成逐篇产物

导出任务仍然以原始 HTML 为基础数据源，但不再将后台任务语义限制为“只下载 HTML”。

执行流程调整为：

1. 读取配置中的 `selectedAccountFakeids`。
2. 读取配置中的 `selectedExportFormats`。
3. 若未选择公众号：
   - 不报错。
   - 更新 `lastDownloadFinishedAt`、`lastDownloadSummary`。
   - 摘要内容为“未选择公众号，已跳过本轮定时导出”。
4. 若未选择导出格式：
   - 不报错。
   - 更新 `lastDownloadFinishedAt`、`lastDownloadSummary`。
   - 摘要内容为“未选择导出格式，已跳过本轮定时导出”。
5. 若两者都存在：
   - 仅处理这些 fakeid 下的文章。
   - 仅生成所选格式文件。

### 导出产物

- `HTML`：沿用当前原始 HTML 抓取与落盘逻辑。
- `TXT`：基于 HTML 解析结果生成纯文本逐篇文件。
- `Markdown`：基于渲染后的 HTML 内容转 Markdown 逐篇文件。
- `DOCX`：基于渲染后的 HTML 内容生成逐篇 `docx` 文件。

产物目录使用按批次时间戳切分的方式，避免新任务覆盖旧文件。

### 启用校验

当前“启用前必须已绑定登录态”的逻辑保留。

不新增“启用前必须已选公众号 / 已选格式”的强校验，原因是：

- 用户可能先打开任务开关，再稍后挑选公众号。
- 用户也可能先打开导出任务，再稍后调整格式。
- 配置启用但未选中公众号或格式时，系统通过“安全跳过”即可提供更平滑的体验。

## 接口与模块改动

### 类型

- `types/worker-scheduler.ts`
  - 扩展 `WorkerSchedulerConfig`

### 仓储层

- `server/services/worker/repository.ts`
  - 配置表迁移
  - 配置字段读写与快照返回
  - 提供“按 fakeid 查询已托管公众号”和“按 fakeid 过滤导出候选文章”能力

### 调度层

- `server/services/worker/scheduler.ts`
  - 同步任务只处理选中账号
  - 导出任务只处理选中账号文章

  - 统一处理 `html/txt/markdown/word`
  - 负责格式文件写入与批次目录组织

### API 层

- `apis/worker.ts`
- `server/api/web/worker/scheduler.post.ts`
- `server/api/web/worker/scheduler.get.ts`

### 设置页

## 错误处理

- 若配置中的 fakeid 已不在托管账号池中：
  - 任务执行时自动忽略失效 fakeid。
  - 前端在加载配置时，仅展示当前仍可用的账号。
- 若配置字段 JSON 解析失败：
  - 回退为空数组。
  - 不阻塞页面加载与任务调度。
- 若保存时携带非法 fakeid 或非法格式值：
  - 服务端过滤掉空值、重复项与不受支持的格式。
  - 不因为单个非法值导致整体保存失败。
- 若服务端缺少 `DOCX` 所需导出能力：
  - 在实现阶段补齐服务端 `docx` 生成方案，避免继续依赖浏览器侧 `window.htmlDocx`。

## 测试策略

优先补最小回归测试，覆盖以下行为：

1. 配置中存在选中 fakeid 时，同步任务只同步这些公众号。
2. 配置中存在选中 fakeid 与格式时，导出任务只处理这些公众号，并只生成所选逐篇格式。
3. 配置启用但未选择公众号时，任务输出“已跳过”摘要，不自动关闭开关。
4. 导出任务启用但未选择格式时，任务输出“已跳过”摘要，不自动关闭开关。
5. 设置页在 `isDirty === true` 时，轮询刷新不会覆盖未保存表单。

如果现有测试基础不足，先补服务端脚本级测试或最小单元测试，以锁定行为回归。

## 方案权衡

选择“单一公众号选择列表 + 单一逐篇格式选择列表”而不是为不同任务维护多套范围配置，原因是：

- 与当前用户需求完全一致。
- 认知负担最低，设置页不会因为多套选择而变复杂。
- 与当前仓库能力边界匹配，避免把 `Excel/JSON` 这类汇总型导出硬塞进后台任务。
- 为后续扩展保留空间；若未来确实需要拆分，可以在此基础上平滑演进。

## 验收标准

- 用户可在设置页明确选择参与后台任务的公众号。
- 用户可在设置页明确选择后台逐篇导出的格式。
- 未选择公众号时，任务不会跑全部账号，也不会自动关闭。
- 未选择格式时，导出任务不会默认回退到 HTML，也不会自动关闭。
- 定时同步与定时导出都仅处理选中的公众号。
- 定时导出仅生成用户选择的逐篇格式，`Excel/JSON` 仍通过手动导出完成。
- 设置页开关、输入框、多选项在未保存前不会被轮询回写覆盖。
