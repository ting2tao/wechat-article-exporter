# 定时任务显式选择公众号设计

## 背景

当前后台定时任务存在两个影响可用性的问题：

1. 定时同步与 HTML 下载默认面向全部托管公众号执行，用户无法显式指定任务范围。
2. 设置页每 15 秒轮询一次服务端快照，并且会无条件覆盖本地表单，导致用户在尚未保存时看到开关或输入内容被“自动改回去”，表现为“开启后自动关闭”。

这两个问题叠加后，用户既无法精确控制任务对象，也无法稳定配置定时任务。

## 目标

- 定时任务不再默认作用于全部公众号，必须由用户显式选择公众号后才会执行。
- 公众号同步与 HTML 下载复用同一组已选公众号范围。
- 当未选择任何公众号时，任务保持启用状态，但本轮执行应被安全跳过，并给出明确摘要。
- 设置页轮询不得覆盖用户尚未保存的编辑内容。

## 非目标

- 不为“公众号同步”和“HTML 下载”分别维护两套不同的公众号选择。
- 不改变现有托管公众号的来源与维护方式，账号页仍然负责向服务端写入可选账号池。
- 不新增复杂的调度策略，例如按账号设置不同间隔或优先级。

## 当前实现问题

### 任务范围

- `server/services/worker/scheduler.ts` 中的同步任务直接遍历 `listTrackedAccounts()` 返回的全部账号。
- HTML 下载任务通过 `downloadPendingHtmlBatch()` 统一处理待下载文章，未按公众号范围过滤。
- 设置配置 `WorkerSchedulerConfig` 中不存在任务范围字段，因此前端无法表达“只运行部分公众号”。

### 设置回弹

- `components/setting/Schedule.vue` 每 15 秒执行 `refreshSnapshot()`。
- `applySnapshot()` 会无条件将服务端配置回写到 `form`。
- 当用户编辑但尚未保存，或者保存失败后，轮询就会把本地表单恢复成旧值，造成“自动关闭”与“输入被吃掉”的观感。

## 方案概述

采用单一配置源方案：在后台任务配置中新增 `selectedAccountFakeids` 字段，保存“当前允许参与定时任务的公众号 fakeid 列表”。同步任务与 HTML 下载任务均只读取这组 fakeid 作为范围约束。

同时，在设置页引入“表单脏状态”保护。用户修改表单后，在未保存前，轮询只更新运行状态和统计信息，不覆盖本地编辑值。

## 数据模型调整

### `WorkerSchedulerConfig`

新增字段：

- `selectedAccountFakeids: string[]`

语义：

- 为空数组表示“未选择公众号”，不是“全部公众号”。
- 后台任务在配置启用但列表为空时，应跳过执行并输出说明。

### SQLite 配置表

`worker_scheduler_config` 新增列：

- `selected_account_fakeids TEXT NOT NULL DEFAULT '[]'`

存储规则：

- 使用 JSON 字符串持久化数组。
- 读取时进行 JSON 解析，解析失败则回退为空数组。
- 写入时去重、过滤空值，并统一序列化。

### 快照接口

`/api/web/worker/scheduler` 的读写响应中都增加 `selectedAccountFakeids`。

## 前端设计

### 设置页展示

在“公众号同步”卡片中新增“选择公众号”区域：

- 数据源：服务端已托管公众号列表。
- 展示信息：公众号昵称，必要时附带 fakeid 作为辅助识别。
- 支持多选。
- 文案明确说明“后台同步与 HTML 下载都会限制在这里选中的公众号范围内”。

HTML 下载卡片不重复提供第二套选择控件，只展示说明文案，复用同步卡片中的选择结果。

### 表单状态

新增本地状态：

- `selectedAccountFakeids`
- `isDirty`

行为规则：

- 用户修改任一字段后，将 `isDirty` 置为 `true`。
- 轮询刷新时：
  - 始终更新运行状态、执行结果、统计值。
  - 仅当 `isDirty === false` 时，才完整回写配置表单。
- 保存成功后：
  - 用服务端返回值完整回填表单。
  - 将 `isDirty` 重置为 `false`。
- 保存失败后：
  - 保留本地编辑值，便于用户继续调整或重试。

## 服务端行为设计

### 同步任务

执行流程调整为：

1. 读取配置中的 `selectedAccountFakeids`。
2. 从 `listTrackedAccounts()` 中筛出被选中的账号。
3. 若筛选结果为空：
   - 不报错。
   - 更新 `lastSyncFinishedAt`、`lastSyncSummary`。
   - 摘要内容为“未选择公众号，已跳过本轮同步”。
4. 若有选中账号，仅同步这些账号。

### HTML 下载任务

HTML 下载服务需要支持按 fakeid 集合过滤待下载文章。

执行流程调整为：

1. 读取配置中的 `selectedAccountFakeids`。
2. 若为空：
   - 不报错。
   - 更新 `lastDownloadFinishedAt`、`lastDownloadSummary`。
   - 摘要内容为“未选择公众号，已跳过本轮 HTML 下载”。
3. 若非空，仅处理这些 fakeid 下待下载的文章。

### 启用校验

当前“启用前必须已绑定登录态”的逻辑保留。

不新增“启用前必须已选公众号”的强校验，原因是：

- 用户可能先打开任务开关，再稍后挑选公众号。
- 配置启用但未选中公众号时，系统通过“安全跳过”即可提供更平滑的体验。

## 接口与模块改动

### 类型

- `types/worker-scheduler.ts`
  - 扩展 `WorkerSchedulerConfig`

### 仓储层

- `server/services/worker/repository.ts`
  - 配置表迁移
  - 配置字段读写与快照返回
  - 提供“按 fakeid 查询已托管公众号”和“按 fakeid 过滤文章下载候选”能力

### 调度层

- `server/services/worker/scheduler.ts`
  - 同步任务只处理选中账号
  - 下载任务只处理选中账号文章
  - 空选择时输出跳过摘要

### 下载层

- `server/services/worker/html-downloader.ts`
  - 接收可选 fakeid 过滤条件
  - 仅处理指定账号文章

### API 层

- `apis/worker.ts`
- `server/api/web/worker/scheduler.post.ts`
- `server/api/web/worker/scheduler.get.ts`

### 设置页

- `components/setting/Schedule.vue`

## 错误处理

- 若配置中的 fakeid 已不在托管账号池中：
  - 任务执行时自动忽略失效 fakeid。
  - 前端在加载配置时，仅展示当前仍可用的账号。
- 若配置字段 JSON 解析失败：
  - 回退为空数组。
  - 不阻塞页面加载与任务调度。
- 若保存时携带非法 fakeid：
  - 服务端过滤掉空值与重复项。
  - 不因为单个非法值导致整体保存失败。

## 测试策略

优先补最小回归测试，覆盖以下行为：

1. 配置中存在选中 fakeid 时，同步任务只同步这些公众号。
2. HTML 下载只处理选中 fakeid 对应文章。
3. 配置启用但未选择公众号时，两类任务都输出“已跳过”摘要，不自动关闭开关。
4. 设置页在 `isDirty === true` 时，轮询刷新不会覆盖未保存表单。

如果现有测试基础不足，先补服务端脚本级测试或最小单元测试，以锁定行为回归。

## 方案权衡

选择“单一选择列表复用同步与下载”而不是为两类任务配置两套列表，原因是：

- 与当前用户需求完全一致。
- 认知负担最低，设置页不会因为多套选择而变复杂。
- 为后续扩展保留空间；若未来确实需要拆分，可以在此基础上平滑演进。

## 验收标准

- 用户可在设置页明确选择参与后台任务的公众号。
- 未选择公众号时，任务不会跑全部账号，也不会自动关闭。
- 定时同步与 HTML 下载都仅处理选中的公众号。
- 设置页开关、输入框、多选项在未保存前不会被轮询回写覆盖。
